## 1. 产品概述

### 1.1 背景

用户（个人）每天都会产生多笔消费，目前缺乏一个顺手的工具来持续记录和回顾自己的收支情况。市面上的记账产品普遍存在功能臃肿、广告多、开屏推销理财产品等问题，而用户的核心诉求其实非常简单：**快速记一笔，看得懂自己的钱花在哪了**。

因此计划打造一款「小而美」的个人财务管理工具，聚焦「记录 + 统计」两件事，做到打开即记、3 秒完成一笔记账。

### 1.2 产品定位

一款轻量级的个人日常收支记录与统计分析工具。

- **核心价值**：极低摩擦地记录每笔消费，用直观的报表帮助用户理解自己的消费结构，辅助控制开支。
- **产品原则**：
  1. 快 —— 记一笔画的操作路径不超过 3 步 / 3 秒；
  2. 简 —— 首版不做社交、不做理财推荐、不做复杂复式记账；
  3. 可信 —— 数据属于用户，提供导出能力，不丢失、不锁死。

### 1.3 目标用户

| 用户画像 | 描述 | 核心诉求 |
| --- | --- | --- |
| 主要用户：个人日常记账者 | 有稳定收入，每天有数笔消费，希望掌握自己的收支情况 | 快速记录、月度汇总、分类占比 |
| 次要用户：预算控制者 | 希望控制开支、养成储蓄习惯 | 设置预算、超支提醒、趋势对比 |

> MVP 阶段为单用户个人使用，不考虑多用户协作、家庭共享账本等场景。

### 1.4 产品目标（V1.0）

1. 用户可在 3 秒内完成一笔消费记录；
2. 用户可查看任意月份的收支汇总、分类占比与趋势；
3. 用户可设置月度预算并获得超支提醒；
4. 用户数据可导出备份（CSV）。

### 1.5 非目标（明确不做）

- ❌ 复式记账 / 专业会计功能
- ❌ 银行卡、支付宝、微信账单自动同步
- ❌ 理财产品推荐、投资建议
- ❌ 社交功能（好友、晒账单、排行榜）
- ❌ 多币种、汇率换算（V1.0 仅支持人民币 CNY）

## 2. 用户场景与用户故事

### 2.1 典型使用场景

**场景一：随手记一笔（高频，每天多次）**
> 小王中午花 28 元点了外卖。他打开应用，默认进入记账页，输入 28，点选「餐饮-外卖」分类，点击保存。全程约 2 秒。

**场景二：月底复盘（中频，每月 1~3 次）**
> 月底，小王打开统计页，查看本月总支出、各分类占比，发现「购物」类支出异常偏高，点击该分类下钻查看具体账单明细，决定下月控制该类目开销。

**场景三：预算控制（中频）**
> 小王给本月设置了 3000 元总预算和 1200 元餐饮预算。当餐饮支出达到预算的 80% 时，应用内出现提醒；超支后首页预算进度条变红。

**场景四：补记与修正（低频）**
> 小王晚上想起下午打车花了 15 元忘记记录，进入账单列表补记一笔，并将日期改为今天下午；又发现早上一笔金额输错，点击该笔账单进行编辑。

## 4. 功能需求详述

### 4.1 快速记账（P0）—— 核心功能

**入口**：应用底部导航栏中央的「+ 记一笔」按钮，任意页面一键直达；应用启动后若当日无记录，默认落在记账页。

**页面元素与交互**：

1. **类型切换**：顶部 Tab 切换「支出 / 收入」，默认「支出」。
2. **金额输入**：
   - 页面主体为数字键盘，打开即聚焦，无需二次点击；
   - 支持最多 2 位小数，单笔金额上限 9,999,999.99；
   - 支持加减连续运算（如 `12.5 + 8` 自动计算为 `20.5`）；
   - 金额为空或为 0 时保存按钮置灰。
3. **分类选择**：
   - 以宫格图标形式展示分类（支出/收入各自独立分类集）；
   - 默认选中用户上一次使用的分类逻辑：首次使用选中「餐饮」，之后按用户最近 7 天使用频率排序，高频分类靠前；
   - 分类支持左右滑动查看更多。
4. **日期选择**：默认「今天」，点击可切换为其他日期（仅允许选择今天及以前的日期，补记场景）。
5. **备注**：可选，单行文本，上限 50 字。
6. **保存**：
   - 点击「保存」后立即落库，显示轻提示（Toast）「已记录 ¥28.00 餐饮」，并停留在记账页，便于连续记录；
   - 保存成功后键盘与金额清空，分类保留为本次所选。

**业务规则**：

- BR-01：金额必填且 > 0；
- BR-02：分类必选（有默认值，用户不可提交空分类）；
- BR-03：日期不可晚于今天；
- BR-04：单笔记录生成后携带唯一 ID、创建时间、更新时间；
- BR-05：弱网/离线状态下必须可正常保存（数据先写本地）。

**验收标准**：

- 从点击「记一笔」到保存成功 ≤ 3 秒（不含用户输入时间）；
- 连续记录 5 笔无卡顿、无数据丢失；
- 杀掉应用重新打开，记录完整存在。

### 4.2 账单流水（P0）

**入口**：底部导航「账单」。

**页面结构**：

1. **月份切换**：顶部显示当前月份（如「2026年10月」），左右箭头或滑动切换月份；
2. **月度概览条**：显示当月「收入 / 支出 / 结余」三个汇总数字；
3. **按日分组列表**：
   - 每组表头：日期（今天/昨天/周几 + 日期）+ 当日收支小计；
   - 每行：分类图标、分类名、备注（无备注则显示分类名）、金额（支出显示 `-`，收入显示 `+`，用颜色区分）；
   - 默认按日期倒序（最新在前），单日 100 条以内一次性渲染，超出使用虚拟列表/分页。

**交互**：

- 点击某笔账单 → 进入账单详情页（展示全部字段），提供「编辑」「删除」操作；
- **编辑**：复用记账页组件，可修改金额、分类、日期、备注；保存后更新该笔记录的更新时间；
- **删除**：二次确认弹窗（「删除后不可恢复，确认删除这笔 ¥28.00 的支出吗？」）；确认后该笔从列表移除，统计数字实时刷新；
- 列表为空时展示空状态插画 + 「记第一笔」引导按钮。

**业务规则**：

- BR-06：删除为单条操作（批量删除列入 P1，需逐条确认或全选确认）；
- BR-07：编辑/删除操作后，所有相关统计（月度汇总、分类占比、预算进度）必须同步刷新。

### 4.3 统计报表（P0）

**入口**：底部导航「统计」。

**4.3.1 月度汇总（P0）**

- 维度切换：按月查看，支持左右切换月份；
- 核心指标卡：本月总支出、总收入、结余（收入-支出）、日均支出（总支出 ÷ 已过天数）；
- 环比：显示与上月同期（截至同一日）的支出变化百分比，上升珊瑚红 ↑、下降柔绿 ↓（遵循国内涨跌配色习惯，色值见 5.6.1 语义色）。

**4.3.2 分类占比（P0）**

- 图表：环形图（Donut）展示本月支出各分类占比；
- 图例列表：按占比降序展示「分类名、金额、占比%」；
- 交互：点击扇区或图例项 → 下钻展示该分类当月全部账单明细（复用流水列表组件）。

**4.3.3 趋势分析（P1）**

- 柱状图展示近 6 个月每月总支出/总收入（可切换）；
- 点击某月柱体 → 跳转至该月的月度汇总。

**业务规则**：

- BR-08：统计口径 = 账单日期（而非创建时间）落在所选月份的记录；
- BR-09：收入不计入支出占比；结余可为负数；
- BR-10：当月无任何记录时展示空状态，不显示为 0 值图表造成误解（0 与无数据要区分）。

**验收标准**：

- 1000 条账单记录下，统计页首屏渲染 ≤ 1 秒；
- 新增/编辑/删除账单后返回统计页，数字与流水一致。

### 4.4 分类管理（P0 内置 / P1 自定义）

**内置默认分类**：

| 支出分类 | 收入分类 |
| --- | --- |
| 餐饮、交通、购物、日用、居住（房租水电）、娱乐、医疗、学习、通讯、运动、宠物、人情（红包礼金）、其他 | 工资、奖金、理财收益、兼职、红包、报销、其他 |

**自定义能力（P1）**：

- 新增分类：名称（≤ 6 字）+ 图标（从内置图标库选择）+ 颜色；名称在同一类型（支出/收入）下不可重复；
- 编辑分类：修改名称/图标；
- 删除分类：仅允许删除无账单引用的分类；若已有账单引用，提示「该分类下有 N 笔账单，需先将其移动到其它分类」，提供批量移动；
- 排序：长按拖动调整记账页分类宫格顺序；
- 系统内置的「其他」分类不可删除。

### 4.5 预算管理（P1）

- **设置入口**：统计页或「我的」页 →「预算设置」；
- **总预算**：设置每月总支出预算（正数，允许小数）；
- **分类预算**：可为任意支出分类单独设置月度预算；
- **预算展示**：
  - 首页/统计页顶部显示预算进度条：`已支出 / 总预算`，附剩余金额与「每日可用」（剩余 ÷ 本月剩余天数）；
  - 进度颜色：0–79% 柔绿 `#7ECBA1`，80–99% 奶油橙 `#FFC96B`，≥100% 珊瑚红 `#FF7B8A`（与 5.6 粉嫩色板统一）；
- **提醒机制**：
  - 当月支出达到总预算 80% 时，应用内横幅提醒一次（每月每类提醒仅一次，避免打扰）；
  - 超支时进度条变红并显示超支金额；
  - 提醒为应用内展示（本地通知列入 P2，视平台能力）。
- **业务规则**：
  - BR-11：预算按月生效，每月 1 日 0 点自动重置进度；
  - BR-12：预算设置为 0 或清除即视为未开启预算功能；
  - BR-13：编辑/删除账单后预算进度实时重算。

### 4.6 搜索与筛选（P1）

- 账单页顶部搜索框：
  - 关键词：匹配备注与分类名；
  - 筛选条件：类型（支出/收入）、分类（多选）、金额区间、日期区间；
- 结果按日期倒序展示，支持在结果中直接编辑/删除；
- 无结果时展示空状态与「清除筛选」按钮。

### 4.7 数据导出（P2）

- 「我的 → 数据管理 → 导出账单」；
- 选择时间范围（某月/某年/全部），导出 CSV 文件；
- CSV 字段：日期、类型、分类、金额、备注、创建时间；
- 编码 UTF-8（含 BOM，保证 Excel 打开不乱码）。

### 4.8 我的 / 设置（P0 基础）

- **我的页（P0）**：展示累计记账天数、总账单数、连续记账天数（轻量激励）；入口：预算设置、分类管理、数据导出、关于；
- **设置项（P1）**：每周起始日（周一/周日，影响周维度统计）；
- **关于（P0）**：版本号、用户协议与隐私政策链接。

## 5. 非功能需求

### 5.1 性能

| 指标 | 要求 |
| --- | --- |
| 应用冷启动 | ≤ 2 秒（P90） |
| 记账保存响应 | ≤ 300ms |
| 账单列表加载 | 1000 条内首屏 ≤ 1 秒 |
| 统计页渲染 | 1000 条内 ≤ 1 秒 |

### 5.2 数据安全与隐私

- 所有账单数据**仅存储于用户本地**（MVP 不上传服务器，无账号体系）；
- 不采集与记账无关的个人信息；无广告、无第三方追踪 SDK；
- 隐私政策中明确说明数据存储位置与导出方式；
- 若后续版本引入云备份，需传输加密（TLS）与存储加密，并单独征得用户同意。

### 5.3 可靠性

- 本地数据库写入需保证原子性，异常退出不丢失已保存记录；
- 应用升级时数据库结构变更需提供迁移方案，不得丢失历史数据。

### 5.4 兼容性与体验

- MVP 形态：**移动端优先的 Web 应用（H5）**，适配 iOS Safari / Android Chrome / 微信内置浏览器；
- 屏幕适配：320px – 480px 宽度为主，兼顾平板；
- 单手可完成全部核心操作（关键按钮位于屏幕下半部）；
- 数字键盘输入区域按钮不小于 44×44pt，防误触；
- 深色模式列入 P2。

### 5.5 可用性目标

- 新用户无任何引导说明的情况下，能在 10 秒内独立完成第一笔记账。

### 5.6 视觉设计规范（粉嫩可爱风）（P0）

**整体风格定位**：粉色系、低饱和、奶油质感的「可爱手账风」。视觉上传达轻松、无压力的记账氛围，避免金融类产品常见的深色、冷色、严肃感。

#### 5.6.1 色彩规范

**主色板**

| 角色 | 色值 | 使用场景 |
| --- | --- | --- |
| 主色（樱花粉） | `#FF9EBB` | 主按钮、选中态、Tab 高亮、核心数字强调 |
| 主色-深（蜜桃粉） | `#F76C99` | 按钮按下态、重要金额（如本月总支出） |
| 主色-浅（奶粉） | `#FFD9E4` | 选中项背景、标签底色、进度条底槽 |
| 页面背景（奶油白） | `#FFF7FA` | 全局页面背景 |
| 卡片背景 | `#FFFFFF` | 内容卡片，搭配柔和投影 |

**辅助色板（糖果色系，用于分类图标与图表）**

| 色名 | 色值 | 示例用途 |
| --- | --- | --- |
| 奶油黄 | `#FFE5B4` | 餐饮、购物类图标底色 |

**中性色与语义色（全部做柔化处理，不使用纯黑与高饱和警示色）**

| 角色 | 色值 | 说明 |
| --- | --- | --- |
| 正文文字（暖灰棕） | `#5A4A4E` | 替代纯黑，减少冷硬感 |
| 次要文字 | `#A79599` | 辅助信息、占位符 |
| 成功/下降（柔绿） | `#7ECBA1` | 预算健康、支出环比下降 |
| 提醒/预警（奶油橙） | `#FFC96B` | 预算 80%–99% |
| 错误/超支（珊瑚红） | `#FF7B8A` | 删除确认、预算超支、支出环比上升 |

**色彩使用原则**：

- 全局以「奶油白背景 + 白色圆角卡片 + 粉色点缀」为基调，主色在单屏中的占比不超过 20%，避免大面积粉色造成视觉疲劳；
- 支出一律用珊瑚红 `#FF7B8A` 系、收入用薄荷绿 `#7ECBA1` 系显示符号与金额颜色；
- 图表（环形图/柱状图）使用辅助色糖果色系，同一图表内颜色间隔取用保证区分度，禁用高饱和撞色与深色系；
- 所有色值需通过对比度检查：正文文字与背景对比度 ≥ 4.5:1（`#5A4A4E` on `#FFF7FA` 已满足）。

#### 5.6.2 形状、图标与字体

- **圆角**：卡片圆角 20px，按钮采用全圆角胶囊形（pill），输入框圆角 12px；全局禁止直角锐利边缘；
- **投影**：卡片使用柔和粉色系投影（如 `0 4px 16px rgba(255, 158, 187, 0.15)`），不使用灰色重投影；
- **图标**：分类图标采用「圆胖线条 + 糖果色圆底」风格，线宽 2px、端点圆角；空状态与引导插画使用可爱贴纸风（存钱罐、小猫、爱心等元素）；
- **字体**：中文优先圆体系（苹方-简 / 思源黑体圆体 / HarmonyOS Sans 回退），金额数字使用圆体数字或 `DIN Round` 类圆角数字字体，强化软萌感；
- **金额展示**：大数字金额（月度总支出等）可适当加入主色-深强调。

#### 5.6.3 动效与微交互（可爱感的关键）

| 场景 | 动效要求 | 优先级 |
| --- | --- | --- |
| 保存记账成功 | Toast 附带小爱心/星星弹跳动画（≤ 600ms） | P0 |
| 按钮按下 | 轻微缩放（scale 0.95）+ 回弹 | P0 |
| 分类选中 | 图标弹跳一下 + 底色渐变为奶粉色 | P0 |
| 预算进度条 | 数值变化时平滑过渡（300ms ease-out） | P1 |
| 月度切换 | 图表数字滚动过渡 | P2 |

- 动效原则：轻快、有弹性（spring 曲线），单次动效时长不超过 600ms，不打断连续记账操作。

#### 5.6.4 验收标准

- 全部页面色彩取自本节色板，无游离色值（可通过设计 token / 变量统一管理）；
- 深色模式（P2）届时基于同一色板做暗色映射，不重新设计。

## 6. 信息架构与页面流

### 6.1 信息架构

```
底部导航（3 Tab + 中央按钮）
├── 首页（今日概览：今日支出、本月支出、最近 5 笔）
├── 账单（月度流水 + 搜索筛选）
├── ＋（记一笔 —— 中央悬浮按钮）
├── 统计（月度汇总 / 分类占比 / 趋势）
└── 我的（成就、预算设置、分类管理、数据导出、设置、关于）
```

### 6.2 核心页面流

```
启动应用 → 首页（今日概览）
   ├─ 点「＋」 → 记账页 → 输入金额/选分类 → 保存 → Toast → 停留记账页（可连续记）
   ├─ 点「账单」 → 月流水 → 点某笔 → 详情 → 编辑/删除
   └─ 点「统计」 → 月度汇总 + 分类环形图 → 点分类 → 下钻明细
```

## 8. 数据埋点与成功指标

### 8.1 北极星指标

**周活跃记账笔数**（Weekly recorded bills）——衡量产品是否真正被用于持续记录。

### 8.2 关键指标

| 指标 | 定义 | V1.0 目标（自用基线） |
| --- | --- | --- |
| 记账完成率 | 进入记账页后成功保存的比例 | ≥ 90% |
| 单笔记账耗时 | 从打开记账页到保存成功 | P90 ≤ 5 秒 |
| 连续记账留存 | 连续 7 天有记账行为的周占比 | ≥ 60% |
| 统计页使用率 | 每周至少打开 1 次统计页 | ≥ 1 次/周 |
| 崩溃率 | 会话异常退出比例 | < 0.1% |

### 8.3 关键埋点事件

`app_launch`、`record_save`（含 type/category/耗时）、`bill_edit`、`bill_delete`、`stats_view`、`budget_set`、`budget_alert_shown`、`export_click`。

> 注：MVP 无账号体系，埋点仅做匿名本地统计或最小化上报，遵循 5.2 隐私要求。
